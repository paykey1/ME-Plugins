# 插件调试与脱敏日志

开发、安装和调试插件不需要 ME 主体源码。支持本功能的 ME 版本在插件设置中提供“开发者调试日志”；插件工作区可通过 `(await MEPlugin.ready()).features?.includes('debug-logs')` 检测接口支持。不能把文档更新视为已安装的旧版 ME 自动拥有该功能。

## 用户操作

1. 打开插件中心，点击对应插件的“插件设置”，展开“开发者调试日志”。
2. 点击“开启调试”，然后重新执行需要排查的操作。后台任务应在开启后重新开始，开启前的记录不能补录。
3. 点击“刷新”查看保留和丢弃数量；点击“导出脱敏日志”，选择 JSON 保存位置。
4. 检查导出内容，再将日志、插件源码、复现步骤和预期结果交给开发者或 AI。不要额外提供账号凭据。

日志默认关闭，最多同时调试 4 个插件。每个插件的记录仅在本机内存保存，最长 30 分钟，最多 500 条且约 1 MiB；满后淘汰旧记录，相邻重复记录合并为丢弃计数。到期后下次访问会清理，重启 ME 不保留。日志不会自动上传到插件作者、插件市场或 AI。

“清空日志”保留调试开关，但正在执行的旧后台任务不再写入，应重新发起任务复现。“关闭调试并清空”同时关闭与删除记录。关闭插件窗口不会清除已有记录，后台任务仍可继续记录；关闭的工作区不能继续上报。停用插件会取消执行及关闭工作区，但已收集记录可在调试期限内导出；卸载操作及退出 ME 清空记录。隐私锁定期间拒绝记录、管理与导出。

## 收集内容

- 后台命令开始、完成、失败；API 2 任务使用与 `status(taskId)` 一致的任务编号，旧 API 命令使用独立关联编号。
- 后台捕获到的异常及最多 4 层 `cause`、未处理的 Promise 拒绝、未捕获异常。
- 后台进程标准输出和错误输出，包含普通 `console.log/warn/error` 输出。按完整行收集；超过 8192 字符的行直接丢弃，不导出被切断的凭据片段。
- 工作区未捕获的 JavaScript 错误与未处理的 Promise 拒绝；也可主动上报已捕获的界面错误。

每条记录包含时间、插件标识与版本、事件、级别、错误码（若有）、脱敏消息及 `frames`。后台任务另带命令与关联编号。`frames` 每项提供插件内相对 `file`、`line`、`column`（可能为空）和函数名。导出文件有 `schemaVersion:1`、宿主版本、运行时版本及丢弃计数，且只包含所选插件。

不自动记录命令输入、执行结果、媒体正文、选区内容或账号数据。堆栈只保留插件包内位置，删除宿主和其它绝对路径；网址整体隐藏，常见令牌、Cookie、Authorization、密码、邮箱和长串不透明值被过滤。带凭据的复杂或多行消息可能整条隐藏，以保留安全边界。

## 开发者调用

后台命令不需要为自动收集增加权限或接口调用。正常抛出 `Error` 即可；已捕获且不会继续抛出的错误，可使用 `console.error(error)`，避免打印完整请求对象、响应正文和用户数据。调试不会改变命令原来的失败代码或授权策略。

工作区的已捕获错误可使用以下可选接口：

```js
const context = await MEPlugin.ready();
if (context.features?.includes('debug-logs')) {
  try {
    await MEPlugin.request('diagnostics.log', {
      level: 'error',
      message: String(error.message || 'Operation failed').slice(0, 8192),
      stack: String(error.stack || '').slice(0, 16384)
    });
  } catch {
    // Diagnostic failures must not replace the original operation outcome.
  }
}
```

其中 `error` 为插件捕获的异常。`message` 必填；`stack`、`code`、`level` 可选，级别为 `info`、`warn`、`error`。消息最长 8192 字符、堆栈最长 16384 字符、代码最长 80 字符，多余字段拒绝。返回 `{recorded:true}` 或 `{recorded:false}`；关闭调试或超限可能返回 false。每个工作区每分钟最多 60 次主动报告，自动错误收集另有每分钟 30 次的发送上限。不需要新增权限，但必须有有效、可见的工作区；插件不能自行开启调试、读取其它插件日志或发起日志导出。开关和导出由 ME 主体界面管理。

`diagnostics.report` 仍是原有的纯数值性能接口，不能用它提交文本日志。

## 限制与验证

这不是操作系统级监控，不能保证捕获原生程序崩溃、插件自行写入的文件日志、未连接的子进程输出或已经被插件吞掉的异常。后台直接调用系统进程仍属于 trusted-native 信任边界。

行号对应已安装插件包中的文件。压缩或打包后的代码可能只有一行；ME 不自动解析 source map，也不随日志附带源码。开发者应提供与版本对应的源码和映射，必要时用保留行号的开发构建复现。

自动脱敏不能识别所有自定义秘密或自然语言中的私人信息。开发者仍须避免记录敏感数据，用户分享前仍需检查文件。日志只是排查线索，不是证明功能正确的测试报告。

交付前验证：关闭调试不留记录；开启后后台及工作区异常有相对位置；中英文操作一致；分享文件无测试凭据和用户路径；导出取消不写文件；清空后旧任务不回写；窗口关闭、停用、卸载及退出行为符合上述约定；高频和超长输出不会无限增长。
